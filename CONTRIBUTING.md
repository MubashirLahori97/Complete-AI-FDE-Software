# Contributing

This is a living curriculum. The best version of it is built by the people doing it.

## Ways to contribute

- **Fix a typo or broken link** — the smallest useful PR.
- **Suggest a better resource** — if you found a clearer free explanation for any day, propose it (one link per day is the rule — it has to *replace*, not add).
- **Sharpen a concept explanation** — if a day's concept can be made obvious in fewer words, that's a great PR.
- **Add a translation** — follow the `01_Day_...` folder structure in your language.
- **Share your solutions** — fork the repo, do the 30 days in public, link your fork in Discussions.

## Ground rules

1. **Concepts 100%.** Every day must be explainable in plain words by a beginner. If a change adds jargon without clarity, it doesn't land.
2. **Specify → evaluate, not just "code."** Days teach directing AI and judging its output — not typing syntax.
3. **One link per day.** The whole point is curation, not collection.
4. **Business lens on every day.** Each day answers: who pays for this, what does it cost, what breaks in production?
5. **Free forever.** No paywalled resources as the primary link.

## How to propose changes

1. Fork the repo.
2. Create a branch: `git checkout -b fix/day-12-link`.
3. Commit with a clear message.
4. Open a pull request describing *why* the change helps a beginner understand the concept better.

Thank you for making the path clearer for the next person. 🚀
