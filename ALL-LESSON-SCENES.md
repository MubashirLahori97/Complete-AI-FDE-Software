# Thirty small discoveries

All thirty core lessons use the illustrated studio direction selected by the learner: dark teal stages, warm gold actions, isometric shapes, quiet supporting text and a visible consequence. FDE Academy, its six-stage course, saved work and actual projects remain connected.

## The learning pattern

1. Start with one question in simple English.
2. Change an input. The local model or real page updates immediately.
3. Look at the scene and current result. Ask what changed and what stayed the same.
4. Try either of two small changes in the scene. Each changes one recognised saved input without replacing unrelated work.
5. Take the idea into the named project with **Build this with AI**. Read its first practical task before starting.

Detailed evidence remains available under **Inspect the numbers and rules**. Guided comparisons, notebook, undo/reset, system/3D inspection, project brief and understanding review remain available. Playing a scene never records mastery.

Lessons 1 and 3 keep a real browser page in the shared teal/gold frame. Lesson 26 keeps its workshop, van and access barrier. The remaining twenty-seven have model-specific SVG illustrations with spatial depth. They do not create additional WebGL applications; existing optional Three.js system inspection remains available.

## What runs

`evaluateLab` remains authoritative. `LessonIllustration.tsx` consumes its typed result; `LessonScene.tsx` connects saved inputs, simple explanations, two single-control comparison changes and the actual project. It does not reimplement business rules. Counted marks say when only a subset is drawn. Full values remain in the detailed evidence. No view implies real customer, provider or deployed-system evidence.

**Follow the idea** highlights three reading moments with a moving explanation cursor. Pause, continue, replay, restart and direct selection are available. This is a finite visual guide, not measured execution. The computed result is visible immediately. Input changes stop previous playback before paint and preserve focus. Reduced motion shows the final moment after an explicit request. There is no automatic or endless playback. Existing opt-in sound supplies a short tone; written information remains sufficient.

The UI/UX skill's verified Animation guidance informed reduced motion, limited movement and playback controls. Applying that guidance is not an observed learning outcome.

## Projects and saved work

Every scene names its actual project, gives its first task and opens the existing Build with AI step. Every ZIP includes a mission-specific `SCENE-GUIDE.md`. Project checks, eight-part system explanations and separate reasoning review remain unchanged. Manual coding is optional; conceptual understanding is compulsory.

Scene edits use existing experiment values, notes, backup and undo/reset. Playback is temporary. Some input changes legitimately leave a result unchanged; explain why rather than inventing visual progress.

## Verification boundary

Check all thirty first actions, visible consequences, fifty-four single-control scene changes, keyboard focus, phone/desktop layouts, evidence disclosure, finite interruption, native actions and every project handoff/download. Retain existing model/course checks and compare published assets with the tested build.

This establishes implementation coverage, not enjoyment, beginner comprehension, retention, professional equivalence, worldwide novelty or a global ranking. Final voice, secondary-page design, representative-device measurements and independent learning trials remain part of the broader standard. Record learner feedback and revise the scenes.
