## Start here

## The idea

A handoff includes opening instructions, configuration, access, recovery and evidence. A provider replacement also needs a compatible interface and a fresh journey check. Source files alone do not establish an operable handoff.

## Things you can change

- **Opening and recovery guide is present:** starts at false.
- **Required operator access is available:** starts at false.
- **Run the replacement journey check:** starts at false.
- **Replacement provider's field:** starts at "status".

## Two guided comparisons

A fresh operator will maintain the product, and a replacement provider uses a different field name.

Each pair loads fictional example inputs and changes one control. Compare the result, then try your own variation. Undo restores earlier values during the current lesson visit; it does not certify understanding.

### 1. Make the replacement fit

Compare the expected key with the actual replacement payload and field assertion.

Starting overrides (other controls use this lab's defaults):

```json
{
  "guide": true,
  "access": true,
  "check": true,
  "field": "status"
}
```

Change one control:

```json
{
  "field": "accessStatus"
}
```

What to understand: The local replacement check now fits its declared contract. A real operator still needs to demonstrate the actual journey and recovery.

### 2. Compatible, but unchecked

Keep the field compatible. Remove the assertion run and inspect the evidence label.

Starting overrides (other controls use this lab's defaults):

```json
{
  "guide": true,
  "access": true,
  "check": true,

```

What to understand: A plausible contract is different from a performed check. An unrun assertion must remain unrun instead of inheriting a success claim.
