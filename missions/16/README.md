# Mission 16: Give an agent a complete task

Stage 4: Direct AI work at greater scale

A completed delegated change with an inspectable decision and evidence record.

AI can perform all implementation, research, planning, tests and diagnosis. Concepts are compulsory. This is a mission, not a one-day guarantee.

## The problem

You want AI to add a useful change, not merely write a function. Give it the goal, context, authority and evidence requirements so it can plan and execute appropriately.

## Understand the concepts

### Goals, context and decomposition

A goal describes the accepted outcome. Context supplies the current system, users, constraints and relevant evidence. Decomposition breaks work into dependencies. AI may propose the plan and revise it; the learner must understand why the parts serve the outcome.

**Example:** Add an access-confirmation filter while preserving existing permissions and saved data.

**Common wrong idea:** A longer prompt or more prescribed steps always gives better delegation.

### Authority, budgets and stopping

Authority defines permitted actions and resources. A budget limits spend, time or work. A stopping condition describes completion or a reason to pause and report. Match controls to consequences and allow routine decisions within the agreed boundary.

**Example:** Work in a test environment; stop if credentials or a paid provider are required.

**Common wrong idea:** An intelligent agent should automatically have unlimited access.

## Predict, change, observe

Choose the authority supplied to a prepared agent task.

Prepared teaching simulation, not live provider or business evidence. Predict before selecting.

- **No boundary stated:** The task leaves spending, publication and data access ambiguous. Capability does not establish authorization.
- **Test environment only:** The agent can work and test locally; external release needs a separate authorized step. A useful boundary permits meaningful work while clarifying consequences.
- **Bounded live change:** Use the named environment, budget and release/recovery conditions. Broader autonomy can be appropriate when its scope is explicit.

Flow: Goal + context + authority (Task brief) → Plan / act / observe (AI workspace + permitted tools) → Accepted outcome + evidence (Actual product review)

## Worked example

**before:** Make the app smarter. Do whatever is needed.

**after:** The agent can choose implementation details and report a result against the brief.

**lesson:** Planning and review can also be delegated. Still connect their claims to the right objective and observations.

## Project: Delegate a complete improvement

Give a capable AI a meaningful change to the visit application. Let it plan, implement, test and diagnose within explicit boundaries.

1. Choose a change and supply the actual system context, outcome, constraints, authority, budget and stopping rules.
2. Let AI propose and execute a suitable plan. Record significant decisions and any needed clarification.
3. Inspect the actual result, repeat a relevant user journey and update the system explanation.

## Understanding, separately from output

- **explain:** Explain how this task permits autonomy without leaving authority ambiguous.
- **locate:** Find the evidence connecting the agent's changes to the requested outcome.
- **predict:** What should happen if the plan needs access outside its allowed scope?
- **compare:** Compare prescribing every edit with delegating an accepted outcome.
- **challenge:** AI says its own successful summary is sufficient acceptance evidence. How would you investigate?

## Reviewer guidance

Ask the learner to change a budget or authority limit and explain the effect on the plan and checks.

AI stays available. A working output plus generated prose does not establish understanding if the learner cannot apply the concept. Practise these variations, then ask a reviewer for a fresh relevant variation:

- The selected tool requires a paid account outside budget. Revise the plan.
- The agent discovers a useful change outside scope. Decide how to handle it.

Record who or what reviewed, the learner's predictions and reasoning, observed results, gaps and next practice. Local review records are not authenticated qualifications.
